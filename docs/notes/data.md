# Слой данных KeySwitch: решения, отклонения, открытые вопросы

Автор: data-dev. Дата: 2026-11-06 (обновлено 2026-11-07, второй проход по ассетам).
Зона: `src/KeySwitch.Data/**`, `tools/BuildAssets/**`.

## Как собрать ассеты

```powershell
dotnet run --project tools/BuildAssets -- --out src/KeySwitch.Data/Assets
```

- Кэш источников: `tools/BuildAssets/obj/cache` (не в git). Повторные запуски идемпотентны
  (фиксированная дата в лицензиях, детерминированная сортировка; проверено несколькими прогонами).
- Полезные ключи: `--force` (перекачать), `--skip-words`, `--skip-ngrams`,
  `--max-words N`, `--max-grams N`, `--cache <dir>`, `--out <dir>`.
- Сборка ассетов ничего не знает про `KeySwitch.Data` (только `KeySwitch.Core` + SharpCompress 0.50.8);
  ассеты подхватываются как `EmbeddedResource Include="Assets\**\*.gz|*.bin|*.txt|*.json"`.
- Корпус Tatoeba читается один раз (`CorpusAnalysis`): частоты словоформ идут в отбор словаря,
  счётчики 3/4-грамм — в модели; это вдвое сокращает время сборки. Полный прогон ~20 с.

## Решения

### Словари слов (`words-*.txt.gz`)

- Источник словоформ — Hunspell `.dic` с раскрытием `SFX`/`PFX` (собственный минимальный
  экспандер: `FLAG short/long/num`, `STRIP`, `ADD`, `CONDITION` с классами `[а-я]` и отрицанием
  `[^...]`, кросс-произведение префикс×суффикс только при `cross`-флаге; continuation-флаги
  (`/` в ADD) и `ICONV` не поддерживаются — в en_US/ru_RU они не используются).
- **Исправлен баг второго прохода**:`ConditionPattern.Token.ParseClass` игнорировал отрицание
  `[^...]` (символ `^` отбрасывался), из-за чего в ru_RU не применялась бо́льшая часть правил
  (например, `SFX K 0 ы [^егхйжкшщч]` для «программист/K» → «программисты»). После фикса
  экспандер даёт 1 294 104 словоформы (было ~1,06 млн) из 146 269 лемм.
- Приоритет отбора (`Candidate.Tier`): 0 — слово из частотного списка FrequencyWords
  (реальная частота), 1 — слово, встреченное в корпусе Tatoeba (частота из корпуса),
  2 — базовая форма `.dic` (лемма), 3 — развёрнутая словоформа с унаследованной частотой
  (`lemmaFreq/20`, иначе 1). Сортировка: tier ↑, частота ↓, для tier 3 — правдоподобность
  окончания ↓ (суммарная частотность последних 3 букв в корпусе), затем `Ordinal`.
  Это даёт: все частотные слова + все встреченные в корпусе формы + все 115 033 леммы
  попадают в лимит, а хвост словоформ добирается формами с типичными окончаниями,
  а не алфавитным обрезом (иначе покрытие было только `а…к`).
- Лимит: **RU 400 000** (кандидатов 1 437 351: частотный список 48 249, корпус 101 691,
  леммы 115 033, словоформы 1 172 378; вошло 135 027 словоформ), **EN 200 000**
  (фактически 98 228 — ограничение словаря). EN лимитируется отдельно
  (`EnglishWordLimit = 200_000`), RU — параметром `--max-words`.
- Валидация алфавита: длина 1..40, только буквы целевого алфавита (кириллица включает `ё`),
  lower-case. Частоты из FrequencyWords 2018 (`ru_50k`, `en_50k`), неизвестные формы получают
  наследованную частоту (≥1), чтобы порядок был детерминированным.
- Известный мусор словаря (`аа`, `ааа`, `ёто`, `ётот`, `zz`, `zzz` и т.п.) оставлен: это
  реальные записи `.dic`, а не ошибка экспандера; на детекцию влияет слабо (нет в частотном
  списке, частота 0/1). Дефисных слов в ru_RU.dic нет вообще, поэтому «из-за» в словаре
  отсутствует по построению; детектору это не мешает — `LanguageScorer` оценивает дефисные
  слова по частям (`ScoreCompound`), и «из»/«за» в словаре есть.

### N-граммы (`ngrams-*-{3,4}.bin`)

- Корпуса Tatoeba (`rus_sentences.tsv.bz2` — 1 233 736 строк, `eng_sentences.tsv.bz2` —
  2 040 024 строки), текст берётся после последнего таба; токенизация — по буквам целевого
  алфавита (пунктуация/цифры — разделители), lower. Слово для обучения — `^слово$`
  (`NgramHasher.Pad`), считаются все 3- и 4-граммы.
- **Порог снижен с `count >= 3` до `count >= 1`** (второй проход): при старом пороге модели
  были почти пустыми (ru-3 10 295, ru-4 47 405), у редких слов per-char log10p упирался
  в floor −6.0 и Δscore был мизерным. Теперь пишутся все встреченные граммы
  (ru-3 12 173, ru-4 62 747, en-3 9 368, en-4 51 866; лимит 400 000 не достигается).
- `log10(p) = max(log10(count / total), −6.0)`: редкая, но встреченная грамма не должна
  быть хуже отсутствующей (иначе `A` уходил ниже floor и Δscore рос искусственно).
  `total` — все учтённые граммы порядка. Отсутствующие граммы потребители трактуют как −6.0.
- Запись строго через `KeySwitch.Core.Text.NgramModelFile.Write` (сортировка по хешу,
  magic/version/order/count). Файлы пишутся в `.tmp` и переименовываются — прерывание
  не оставляет битых ассетов.

### Ё-пары (`yo-ru.txt.gz`)

- Требование контракта: «ё-вариант есть в словаре, е-варианта нет». Проверка кэша показала:
  в ru_RU.dic у **всех** 7 347 ё-слов присутствует е-вариант (146 229 слов), т.е. строгое
  правило даёт 0 пар. Поэтому используется частотная эвристика: пара берётся, если
  е-вариант отсутствует в частотном списке **или** его частота меньше частоты ё-варианта
  (сравнивается `max(FrequencyWords, корпус Tatoeba)`); исключение — whitelist `{еще, ее}`,
  которые безопасны всегда. Отброшено 1 621 неоднозначный случай (`все`, `узнаем`, `поем`,
  `берет`, `мел`, `осел`, …), лимит 30 000 пар достигнут.
  Это осознанное отклонение — см. ниже.

### Опечатки (`typos-*.txt`)

- Курируемые списки, формат `неверно=верно`, `#`-комментарии разрешены. Только однозначные
  пары; намеренно исключены `также`, `вовремя`, `наверно` (корректные слова/формы).
  Многословные замены (`то есть`, `в течение`, `a lot`, `don't`) поддержаны потребителем
  (`TypoCorrector` заменяет слово целиком, включая пробельные варианты — проверено smoke-тестом).
- `TypoDictionary` при первом запуске выкладывает встроенные файлы в `%APPDATA%\KeySwitch`,
  дальше пользователь может их править (`SetEntry`/`Save`/`ResetToDefaults`).

  сохранении копирайта), `ru_RU` — Alexander I. Lebedev (BSD-подобная, требует явно помечать

### Runtime-слой

- `AppSettings`: JSON camelCase (`JsonSerializerDefaults.Web`), атомарная запись
  (`*.tmp` → `File.Replace`, fallback `File.Move`), битый файл → `<файл>.bad` + дефолт.
- `LanguageResources`: ленивая потокобезопасная загрузка embedded-ресурсов с кэшем;
  имена — `KeySwitch.Data.Assets.<имя>`; `IsLoaded` — все 6 базовых ресурсов.
- `ExceptionStore`: профили процессов — редакторы/терминалы/IDE (`Code.exe`, `Cursor.exe`,
  `devenv.exe`, `idea64.exe`, `pycharm64.exe`, `WindowsTerminal.exe`, `cmd.exe`,
  `powershell.exe`, `pwsh.exe`) в режиме `ManualOnly` (там пользователь часто намеренно
  печатает в «чужой» раскладке, автопереключение мешает); `mstsc.exe` — `Full`
  (удалённый рабочий стол, обычный ввод). Папка `\Games\` — глобальное правило `Disabled`,
  не список процессов. `CheckWord` → `WordVerdict`: `NotAWord` (цифры/не-буквы/смесь
  алфавитов), `TooShort` (<2 букв), `BlockedByUser`, `TooFrequent` (топ-100 словаря),
  иначе `Allow`. `CanAddWordException` запрещает одиночные буквы, <2 символов, числа,
  смесь алфавитов и топ-100 частотных слов.
- `LearningStore`: хранит только слово + счётчики (`UndoCount`, `AcceptCount`, `Suppressed`,
  `LastSeen`), ключ `слово|ru→en`; при `UndoCount >= UndoThresholdToSuppress` (по умолчанию 3)
  ставит `Suppressed` и, если передан `ExceptionStore`, добавляет слово как исключение
  (`FromLearning = true`). Контекст/история не сохраняются.
- `AppLogger`: `logs/keyswitch.log`, ротация при >2 МБ в `.log.1`, уровни Info/Warn/Error/Debug,
  в `safeMode` — только Warn/Error. Текст набора/буфер никогда не логируется (запрет
  зафиксирован в XML-doc). Сетевой активности в рантайме нет.

## Отклонения от контракта

1. **Ё-пары**: строгое правило «е-варианта нет в словаре» невыполнимо (0 пар); заменено
   частотной эвристикой + whitelist (`еще`, `ее`). См. выше.
2. **Лимит слов RU**: по заданию второго прохода поднят до 400 000 (было 200 000);
   EN ограничен 200 000 и фактически 98 228 (предел словаря). Приоритет отбора — частотный
   список → корпус → леммы → словоформы, а не просто «по частоте»; это тоже отклонение
   от буквального «отбор по частоте», но оно нужно, чтобы все леммы и корпусные формы попали
   в лимит (иначе покрытие словоря было фрагментарным).
3. **Порог n-грамм**: вместо контрактного `count >= 3` используется `count >= 1` (по заданию
   второго прохода); лимит 400 000 на модель не достигается — корпус даёт 9–63 тыс. грамм
   на модель. `log10(p)` снизу ограничен −6.0.
4. **Количество опечаток**: 140 (ru) и 173 (en) пар вместо «~120 каждый» — больше пар
   лучшего качества, все однозначные; лимит в контракте мягкий («~»).
5. **`words-en` меньше лимита**: 98 228 вместо 200 000 — ограничение самого словаря
   (49 568 лемм + корпус + словоформы), добивать мусором не стал.
6. **Hunspell-экспандер упрощён**: не поддерживаются continuation-флаги (сложные цепочки
   аффиксов), `ICONV`, `AF`-алиасы и `COMPOUND*`; в используемых en_US/ru_RU они не
   встречаются (проверено по `.aff`), поэтому результат корректен для этих словарей.
7. **`SharpCompress` 0.50.8**: актуальная стабильная на момент работы; API для bz2 —
   `SharpCompress.Compressors.BZip2.BZip2Stream.Create(stream, CompressionMode.Decompress, ...)`
   (namespace `SharpCompress.Compressors`, не `System.IO.Compression`).

## Не сделано / риски

- **Не сделано**: `typos-*` не проходят через `TypoCorrector` в тестах других слоёв (моя зона
  — только данные); `yo-ru` содержит словоформы словаря, а не только леммы — `YoFixer`
  требует равной длины, это выполняется по построению пар.
- **Не сделано**: 2 слова RU (`слаженной`, `зашумел`) не попали в отбор 400k, поэтому
  остаются 2 непереключённых слова в Evaluate. Полное покрытие всех 1,43 млн словоформ
  не помещается в бюджет памяти (400k слов ≈ 45 МБ heap); при необходимости точного
  покрытия нужно либо поднимать лимит слов с ростом памяти, либо отдельный «полный»
  словарь на диске. Приёмка (≥98 %) выполнена с запасом.
- **Риск**: `words-ru` содержит словарный мусор (`аа`, `ёто`); на скоринг влияет
  незначительно, но при строгой проверке «слово в словаре» может дать ложные срабатывания.
- **Риск**: 400k RU слов дают ~45 МБ managed heap; если приложение упрётся в лимит 80 МБ
  рабочего набора вместе с рантаймом, первым шагом снизить RU до 300k (`--max-words 300000`)
  — по метрикам Evaluate потеря мала, потому что все корпусные формы и леммы остаются.
- **Риск**: ассеты пересобираются ~20–30 с (скачивание закэшировано); при обновлении
  upstream-словарей результат изменится — версии не пинованы (URL master). Для
  воспроизводимости нужно закрепить commit-хеши, если потребуется.
- **Проверено**: `dotnet build src/KeySwitch.Data -v q` — 0 ошибок, 0 предупреждений;
  `dotnet build tools/BuildAssets -v q` — 0/0; `dotnet run --project tools/BuildAssets` —
  идемпотентно, 3,7 МБ; Evaluate RU forward/reverse и EN forward — PASS.
