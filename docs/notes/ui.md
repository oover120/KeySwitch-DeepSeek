# UI-слой KeySwitch — заметки

Автор: app-ui-dev. Зона: `src/KeySwitch.App/Views/**`, `ViewModels/**`, `Themes/**`, `Tray/TrayIconFactory.cs`, `Resources/keyswitch.ico`.
Статус: UI-слой готов, локализация RU/EN с живым переключением готова, `dotnet build src/KeySwitch.App -c Release` проходит без ошибок и предупреждений. Вкладки визуально проверены в обоих темах и обоих языках через тестовый харнесс (`%TEMP%\ksui`, скриншоты в `%TEMP%\ksui\shots`).

## Решения

### Темы и стили
- Два словаря цветов: `Themes/Colors.Light.xaml` и `Themes/Colors.Dark.xaml` (одинаковый набор ключей). Стили — отдельный `Themes/Styles.xaml` (имплицитные + именованные), подключаются один раз.
- `Themes/ThemeManager.cs` (static):
  - `Apply("system"|"light"|"dark")` — выбирает словарь, подменяет его в `Application.Current.Resources.MergedDictionaries`, досыпает `Styles.xaml`; `System` читает `HKCU\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize\AppsUseLightTheme`.
  - Системный акцент — `HKCU\Software\Microsoft\Windows\DWM\ColorizationColor` (0xAARRGGBB), с корректировкой контраста: тёмный акцент высветляется к белому, светлый — притемняется.
  - `ApplyWindowChrome(window)` — `DwmSetWindowAttribute`: 20 = immersive dark mode, 33 = corner preference → DWMWCP_ROUND. Ошибки/отсутствие dwmapi глотаются (деградация на старых Windows).
  - Словари адресуются абсолютным pack-URI `pack://application:,,,/KeySwitch;component/Themes/...`, а не относительным `Themes/...`: относительный WPF разрешает от входной сборки, и в харнессе/тестах (входная сборка чужая) тема не находилась. Имя сборки берётся из `typeof(ThemeManager).Assembly`.
  - `ThemeChanged`, `RefreshOpenWindows()` — живые окна перекрашиваются без перезапуска.
- Шрифт: `AppFontFamily` = "Segoe UI Variable Text, Segoe UI, Arial" (на Win10 останется Segoe UI), для заголовков — `AppFontFamilyDisplay`.
- Скругления: кнопки/поля 8, карточки 12, маленькие элементы 4.
- Стили: Button, TextBox, CheckBox, RadioButton, ComboBox/ComboBoxItem, ListBox/ListBoxItem, TabControl/TabItem, ScrollBar (тонкий оверлейный, кастомные Thumb), Slider (свой трек), ToolTip, ToggleSwitch (ToggleButton 44×24, Win11-вид), SettingRow, CardStyle, TitleBarCloseButtonStyle, AccentButtonStyle, LinkButtonStyle.
- В XAML стили берутся через `DynamicResource` (словари появляются после старта), конвертеры — через `StaticResource` (Binding.Converter — не DependencyProperty, DynamicResource там не работает). Поэтому `ThemeManager.Apply/EnsureInitialized` вызывается до `InitializeComponent` окна.

### Окно настроек
- `Views/SettingsWindow.xaml`: 860×640, `WindowStyle=None` + `WindowChrome` (CaptionHeight=0, ResizeBorderThickness=6, GlassFrameThickness=0). Свой заголовок 40 px с бейджем «KS», названием и кнопкой закрытия. Кнопок свернуть/развернуть нет — окну настроек они не нужны (см. «Отклонения»).
- Вкладки — `TabControl` сверху: «Общие», «Исключения», «Опечатки», «Звуки», «О программе». Каждая — отдельный `UserControl` в `Views/Tabs/`.
- «Общие»: поведение, раннее срабатывание (порог длины), команды клавиш (HotkeyBox), блок «Точность» со слайдером порога уверенности 0.5–5.0 и подписью значения, запуск/безопасность, тема и язык.
- `SettingRow` показывает описание под заголовком (серым, мельче); пустое описание скрывается через DataTrigger. Изначально описание было жёстко свёрнуто — исправлено, теперь строки выше и информативнее.
- Кнопки «Прослушать» в «Звуках» — не текст-глиф «▶», а `Path`-треугольник: символ обрезался шаблоном кнопки на узкой ширине.
- Нижняя панель 56 px: слева сообщение валидации (красное) и статус (серый), справа «Отмена» и «Сохранить» (акцентная, IsDefault = Enter). Esc закрывает окно без сохранения.
- Окно не сохраняет само: `SettingsViewModel.Apply()` → `Saved` → сохранение `settings.json` и применение рантайма на стороне app-dev.

### ViewModels
- Без MVVM-фреймворков: `ViewModelBase` (SetProperty/OnPropertyChanged), `RelayCommand` (CommandManager.RequerySuggested), `OptionLists` (пары value/title для ComboBox), `RowViewModels` (ProcessRow/WordRow/TypoRow).
- `SettingsViewModel` ctor ровно `(AppSettings, ExceptionStore, LearningStore, AppPaths, AppLogger)`. `Reload()` подтягивает настройки/исключения/словарь, `Apply()` = валидация → запись в `AppSettings` → сохранение исключений и словаря опечаток → `Saved`.
- Словарь опечаток редактируется в памяти (`TypoDictionary.SetEntry/RemoveEntry`), сравнение с исходным снимком позволяет удалять записи; `Save()` вызывается один раз в `Apply()`, ошибки ввода-вывода показывает `LastError`.
- Ошибки добавления слов — из `ExceptionStore.CanAddWordException` (тексты готовые, UI их не дублирует).

### Трей
- `Tray/TrayIconFactory.Create(layoutId, enabled, manualOnly)` рисует GDI+ квадрат со скруглением 24 %, надпись «EN»/«RU» белым, фон #2F6FED / #D9534F. Выключено — серый #8A8A8A с перечёркиванием, ручной режим — жёлтая точка в правом верхнем углу.
- Иконка отдаётся многоразмерной (16/24/32/48): кадры рисуются отдельно и собираются в ICO-контейнер в памяти (DIB-кадры, 32 bpp + пустая AND-маска). Так Windows берёт нужный размер под DPI и в 16 px не мылит.
- На случай сбоя сборки контейнера есть запасной путь через `GetHicon` + `Icon.Clone` + `DestroyIcon` (HICON не течёт).

### Ресурсы
- `Resources/keyswitch.ico` — настоящий многоразмерный ICO (16/24/32/48/256), сгенерирован программно: скруглённая тёмная плитка, синяя стрелка вправо (EN) и красная влево (RU). Файл собирается как `ApplicationIcon` csproj.

### Локализация (RU/EN)
- Строки — `Localization/Strings.Ui.cs` (`UiStrings.Ru` / `UiStrings.En`, 152 ключа в каждом, ключи вида `general.title`, `exceptions.addWord`). `Loc` сливает их с runtime-словарями; при смене языка поднимается `PropertyChanged` с пустым именем, и привязки `{Binding [key], Source={x:Static loc:Loc.Instance}}` перечитываются без пересоздания окна.
- Название программы — ключ `app.name` (в заголовке окна и на вкладке «О программе»), версия — из сборки. Ни одной русской UI-строки в XAML не осталось; по-русски остались только комментарии XAML, `_logger.*` и таблица точных текстов `ExceptionStore` (они служат ключами перевода ошибок).
- Сообщения ViewModel хранятся ключом + аргументами (`_statusKey/_statusArgs`, `_validationKey/_validationArgs`, `_processErrorKey`, ...), а свойства форматируют их через `Loc.Format` при чтении — поэтому статус и ошибки переключаются на лету.
- Варианты ComboBox (`ChoiceOption`/`ModeOption`) хранят `TitleKey`, `Title => Loc.T(TitleKey)`; сами экземпляры живут всё время окна, а при смене языка у них обновляется подпись (`RefreshTitle`, `OptionLists.RefreshTitles`).
- **Важно:** списки вариантов нельзя пересоздавать при смене языка. Подмена `ItemsSource` сбрасывает `SelectedItem`, двусторонняя привязка пишет `null` в VM, и ComboBox остаётся пустым (а в строках списков — с красной рамкой ошибки привязки к non-nullable `ExceptionMode`). Поэтому списки создаются один раз, а обновляются только подписи существующих элементов.
- Пустые списки получили локализованные подсказки: «Список пуст: автопереключение работает во всех программах», «Слов пока нет: ...», «Словарь пуст: ...» (ключи `exceptions.processes.empty`, `exceptions.words.empty`, `typos.empty`).
- Английские тексты естественные, не подстрочник: "App is on", "Fix before Space", "Use system theme", "Manual only". Русские данные (слова-исключения, замены, лицензии) не переводятся.
- Описание «Язык интерфейса» честно сообщает, что язык применяется сразу, без перезапуска. `SettingsViewModel.Apply()` вызывает `Loc.Instance.SetLanguage(...)`, поэтому сохранение языка и применение происходят одновременно.

## Отклонения

- Нет кнопок «Свернуть»/«Развернуть» в кастомном заголовке: только закрытие. Окно настроек не масштабируют, а сворачивание дублирует трей. Если нужно — добавляется 10 строками.
- Вкладки горизонтальные сверху (стандартный TabControl), а не левый навбар: требование допускало любой вариант, выбран более предсказуемый и читаемый на 860 px.
- «Прослушать» звук работает через `SoundService.Shared`; если сервис ещё не создан приложением, кнопка честно пишет, что прослушивание доступно из запущенного KeySwitch (а не молча падает). После интеграции с app-dev ограничение снимается само.
- Горячая клавиша паузы — не поле ввода сочетания, а флаг: Pause/Break зафиксирована контрактом `AppSettings` (строкового свойства нет).
- Язык интерфейса применяется сразу через `Loc`; отдельного «перезапустите приложение» больше нет. Переведены только окно настроек и его сообщения — трей и runtime-строки живут в `Strings.Runtime.cs` (зона app-dev).
- Тёмная тема окна и системный акцент применяются сразу; при смене системной темы на лету уже открытые окна получают цвет только по `ThemeChanged` (без перезапуска, но и без анимации).

## Не сделано / что проверить

- Английские строки трея/уведомлений — не моя зона (`Localization/Strings.Runtime.cs`).
- Визуальная проверка сделана харнессом: `%TEMP%\ksui` поднимает `SettingsWindow` на временных `%TEMP%\ksui\data`, рендерит вкладки в `RenderTargetBitmap` в тёмной и светлой темах (860×640), прокрученные низ/серединку «Общих», низ «Исключений» (пустой список слов), узкое окно 760×560 и экран ошибки валидации. Отдельно проверены живые переключения RU→EN и EN→RU через `vm.LanguageValue` + `Apply()`: культуры `en`/`ru`, статусы «Settings saved.» / «Настройки сохранены.», ComboBox сохраняют выбранные пункты, красных рамок нет. Скриншоты: `%TEMP%\ksui\shots\*.png` (`en-*`, `ru-after-switch.png`).
- В живом окне осталось проверить только то, что не видно в RenderTargetBitmap: DWM-скругление/тёмный заголовок и перетаскивание за кастомный заголовок (окно открывал app-dev — жалоб нет), плюс иконку в настоящем трее.
- Иконки трея проверены отдельным GDI+-тестом на всех состояниях (en/ru/manual/disabled/unknown) в 16–48 px: «EN»/«RU» читаются, бейдж ручного режима не наезжает на текст.
- Нет обработки «изменения настроек другим окном»: `Reload()` есть, но окно одно, событий внешнего изменения не слушает.
- Валидация процессов проверяет имя/путь и дубликаты, но не проверяет существование файла: правило можно добавить для ещё не установленной программы — это осознанно.
- Не добавлены иконки в сами кнопки/вкладки (текстовые подписи) — так спокойнее в 860 px и не нужны внешние ассеты.
- Тёмная тема списков/скроллбаров снята на скриншотах: переполнение длинных списков (процессы, замены) уходит в тонкий оверлейный скроллбар, строки не разъезжаются.
