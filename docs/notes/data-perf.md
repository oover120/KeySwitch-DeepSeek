# Data layer: компактное хранение словарей

Задача: снизить память слоя данных KeySwitch, не меняя поведение и формат ассетов.
Правки только в `src/KeySwitch.Data/**`; `src/KeySwitch.Core`, `src/KeySwitch.App`, хуки,
`src/KeySwitch.Data/Assets/**` и `tools/BuildAssets` не трогались.

## Что изменено

- **`src/KeySwitch.Data/Utf8WordTable.cs` (новый файл).**
  - `Utf8WordTable` — неизменяемая таблица слов: один `byte[]` UTF-8-блоба + `int[]` смещений
    (слово `i` = `blob[offsets[i]..offsets[i+1]]`); ключи отсортированы побайтово, поиск —
    бинарный с `SequenceCompareTo`. Блоб строится с точным размером (без остатка).
  - Дополнительно `int[] _prefix` на 65 537 элементов: диапазоны по первым двум байтам слова
    (короткие слова дополняются нулём). Сужает бинарный поиск с ~400 тыс. слов до нескольких
    тысяч. Для таблиц, к которым не ищут по ключу (значения ё-словаря), не строится.
  - `Utf8Words` — кодирование в нижний регистр инвариантной культуры и UTF-8 в стековые
    буферы (`stackalloc`), поэтому `Contains` не создаёт управляемых аллокаций. Слова длиннее
    64 символов (в ассетах максимум 28) уходят на heap — как и раньше, без изменения поведения.
  - `Utf8WordTableBuilder` — накопление слов, дедупликация «побеждает последняя запись»,
    проверка уже отсортированного входа (ассеты отсортированы), fallback-сортировка через
    `int[]` индексов с пересборкой блоба — без массива строк и без повторного парсинга.
- **`src/KeySwitch.Data/TextAdapters.cs`.** `WordDictionary` переписан на `Utf8WordTable`:
  публичный API сохранён (`IWordDictionary`: `Language`, `Count`, `Contains`, `GetFrequency`),
  `Contains`/`GetFrequency` регистронезависимы как раньше (`ToLowerInvariant`) и в горячем
  пути не аллоцируют строку. `GetMostFrequent(count)` — частичный отбор top-N кучей на N
  элементов вместо `OrderByDescending` по всему словарю; результат кэшируется (N по умолчанию
  256). Кэш не сохраняется для запросов больше 4096 элементов: иначе запрос «все слова» навсегда
  оставлял бы в памяти 400 тыс. строк (раньше так и происходило). `Read`/`ReadGzip` заранее
  оценивают размеры буферов по длине gzip-ассета. `CharNgramModel` не менялся.
- **`src/KeySwitch.Data/YoDictionary.cs`.** 30 000 пар хранятся как две компактные таблицы
  (ключи и значения) + `int[]` ссылок ключ → значение; семантика `TryGetYoWord` прежняя
  (регистронезависимо, `Trim`, последняя запись побеждает).

## Что проверено и оставлено без изменений

- `NgramModelFile`/`NgramModelData`: уже аллоцируют ровно `ulong[count]` + `float[count]`,
  буфер байтов переиспользуется, лишних копий и LOH-всплесков нет.
- `TypoDictionary`: ~313 пар в двух `Dictionary<string,string>`, вклад в память пренебрежим.

## Поведенческие проверки

В харнессе дополнительно проверено (все OK):

- `Contains`/`GetFrequency` регистронезависимы (`привет`/`ПРИВЕТ`/`Привет`), пустая строка →
  `false`/`-1`, отсутствующее слово → `-1`;
- `GetMostFrequent(0/10/100/256/500000)`: размеры, согласованность префиксов, порядок
  «частота по убыванию, при равенстве Ordinal», `count > Count` возвращает все слова без
  исключения;
- `WordDictionary.Read` на заведомо несортированном вводе с дублями регистра: дедупликация,
  побеждает последняя запись, поиск и топ работают;
- `YoDictionary`: 30 000 пар, `автогидроподъемник` → `автогидроподъёмник`, регистронезависимо,
  отсутствующее слово → `false`;
- потокобезопасность чтения после загрузки: 200 тыс. параллельных `Contains` без ошибок
  (`Utf8WordTable` неизменяема, `GetMostFrequent` публикует кэш через `Volatile`).

## Что не сделано / ограничения

- Формат и содержимое ассетов не менялись; сортировка не требуется (ассеты уже отсортированы
  побайтово), fallback-сортировка оставлена для произвольного `TextReader`/`Read`.
- Дальнейшее ускорение поиска возможно хеш-индексом (`uint[]` хешей + open addressing), но это
  +4–6 МБ managed памяти и отход от заказанного бинарного поиска — не делал.
- `peakWS` в харнессе включает накладные расходы рантайма; в реальном процессе приложения
  абсолютные значения другие, но разница «до/после» (≈38–39 МБ) обусловлена словарями.
