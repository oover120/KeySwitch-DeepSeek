# Тесты и стенд Evaluate (зона QA)

Дата: 2026-11-07. Все прогоны — локально, без сети, без прав администратора и без установки реального хука.

## Решения

### Структура тестов

- `src/KeySwitch.Tests/*.cs` — xUnit-тесты по слоям Core и Data:
  - `LayoutConversionTests.cs` — EN↔RU по физическим клавишам, регистр/Shift/CapsLock, знаки и цифры, unmapped-символы, round-trip `Convert(Convert(x)) == x`;
  - `WordBufferTests.cs`, `KeyClassifierTests.cs` — буфер слова (Append/Backspace/Clear/ToToken) и классификация клавиш (WordChar/Terminator/Backspace/Reset/Ignore, Ctrl/Alt/Win, стрелки/Home/End);
  - `DetectorTests.cs` — синтетические словари и n-граммы, пороги A/B, раннее срабатывание, регистр, пунктуация, recall/FP на списках слов;
  - `ImpossibleCombinationsTests.cs`, `WordTextTests.cs`, `PostProcessTests.cs`, `NgramTests.cs`, `CorrectionEngineTests.cs`;
  - `DataTests.cs` — AppPaths, SettingsStore (round-trip и битый JSON), ExceptionStore (валидация слов и направления), LearningStore (порог подавления), интеграционная загрузка реальных ассетов.
- `src/KeySwitch.Tests/TestData/words-ru.txt` (325 слов) и `words-en.txt` (303 слова) — встроенные списки для детектора (в сумме 628 слов, требование «≥ 500 слов» выполнено).
- `src/KeySwitch.Tests/TestSupport/TestResources.cs` — in-memory `IWordDictionary`/`ICharNgramModel` (сглаживание Лапласа), фабрика детектора, поиск TestData с фолбэком от каталога сборки к исходникам.
- `src/KeySwitch.Tests/TestSupport/Fakes.cs` — фейковые `ILearningStore`, `IExceptionPolicy`, `ITypoDictionary`, `IYoDictionary`.

### Стенд `tools/Evaluate`

- Загружает **реальные** встроенные ассеты через `LanguageResources.Load(...)`; если ассеты не собраны — код возврата 2 с пояснением.
- Аргументы: `--corpus <path>`, `--lang ru|en`, `--layout ru|en`, `--reverse`, `--json`, `--limit N`, `--help`.
- Обычный режим: корпус — корректные слова языка `--lang`; `typedText = Convert(natural, natural→typed)`, ожидается переключение.
- `--reverse`: корпус уже содержит текст в неверной раскладке; `natural = Convert(typed, typed→natural)`. В этом режиме токены не обрезаются по «не-буквам» (иначе теряются буквы, набранные как `[ ] , . ; ' < > { }`), а только по символам, отсутствующим в раскладке набора.
- Метрики: recall (доля верных переключений), ложные срабатывания на дедуплицированных корректных словах, точность переключений, мкс/слово, распределение уверенности, топ-50 ошибок с reason из детектора.
- Дополнительно считается recall на подмножестве «целевое слово есть в словаре целевого языка» — это контрактно гарантированный набор (порог ×2,5 для незнакомого кандидата туда не входит).
- Неоднозначные кейсы пропускаются: если набранный текст сам является словом языка набора (по словарю **или** по `LanguageScorer` исходного языка, как это делает сам детектор), переключение запрещено контрактом.
- PASS/FAIL: recall ≥ 98 % и FP ≤ 0,5 %; код возврата 0/1 (2 — ошибка аргументов/ассетов).
- Корпуса: `tools/Evaluate/corpus-sample.txt` (RU, 678 токенов), `tools/Evaluate/corpus-sample-en.txt` (EN, 905 токенов), `tools/Evaluate/corpus-sample-mistyped.txt` (тот же RU-корпус, набранный в EN-раскладке — для `--reverse`).

### Договорённости по нестабильному коду

- 4 теста контракта терминатора в `CorrectionEngineTests.cs` помечены `Skip` с идентификатором **BUG-01**: они фиксируют ожидаемое поведение по `docs/CONTRACTS.md:209,226`, но текущий Core его нарушает. Это позволяет держать `dotnet test` зелёным и одновременно документировать дефект; после исправления Core достаточно снять `Skip`.
- Тесты не требуют установки хука, Elevation/реестра и UI; Data-тесты работают на временных каталогах.
- Core, Data, Hooks, App не изменялись.

## Найденные баги

### BUG-01 (Core, P1): терминатор инвертирован в плане исправления

- Файл: `src/KeySwitch.Core/Engine/CorrectionEngine.cs:220`.
- Код: `var terminatorToType = terminatorAlreadyTyped ? terminator : null;`
- Ожидание по контракту (`docs/CONTRACTS.md:209` — при `CompleteWord(ch, terminatorAlreadyTyped: false)` приложение ставит `Handled = true` и глушит клавишу; `docs/CONTRACTS.md:226` — «Terminator входит в TextToType»): `terminatorAlreadyTyped ? null : terminator`.
- Факт: для `CompleteWord(' ', false)` план получает `Terminator = null`, `TextToType = "привет"` (пробел теряется, слова склеиваются); для `terminatorAlreadyTyped: true` план печатает лишний терминатор, а `DeleteCount = len + 1` удаляет его корректно, но затем вставляет повторно.
- Затронуты и планы постобработки (тот же `deleteCount`/`terminatorToType` в `BuildPlan`).
- Тесты: `CompleteWord_TerminatorNotTyped_TextToTypeContainsTerminator`, `CompleteWord_TerminatorAlreadyTyped_DeletesItAndDoesNotRetype`, `TryUndo_AfterSwitchWithTerminator_DeletesTerminatorToo`, `PostProcess_WithTerminator_IncludesTerminatorInTextToType` — помечены `Skip` (BUG-01) до исправления. После правки одной строки их нужно раскомментировать/снять Skip.
- Ветку `terminatorAlreadyTyped: true` в текущей интеграции Hooks никто не использует (Hooks глушит клавишу), поэтому практический сценарий — именно потеря пробела.

### BUG-02 (Core, косметика): опечатка в публичном имени постпроцессора

- Файл: `src/KeySwitch.Core/PostProcess/PostProcessors.cs:43`: `public string Name => "ИСправление";` — должно быть «Исправление». Влияет на UI/логи, поведение не меняет.

### Наблюдения (не блокируют)

- `YoFixer` (`PostProcessors.cs:118-121`) не сохраняет регистр: «Зеленый» → «зелёный». Контрактом не оговорено; при необходимости — отдельное решение.
- `WordText.SplitTrailingPunctuation` для строки только из пунктуации возвращает её же как ядро (комментарий в коде обещает пустое ядро). Поведение зафиксировано тестом `WordTextTests`; на детектор не влияет, т.к. вызывающий проверяет длину ядра.
- Ассеты: `words-ru.txt.gz` (200 000 слов) не содержит ряда распространённых словоформ («программисты», «понятные», «лужи», «болельщиков», «свернувшись», «слаженной», «ягодами», «из-за»), `words-en` — «restarts», «swirled». Именно это даёт 14 промахов recall на RU и 2 на EN. Решение (расширить словарь / снизить порог для n-грамм / оставить как есть) — за lead, пороги и Core не менялись.

## Не сделано

- Тесты Hooks: слой содержит в основном Win32-обёртки; единственная чистая функция (`LayoutIds`) объявлена `internal`, поэтому без `InternalsVisibleTo` её не протестировать. Реальный хук, отправку ввода и переключение раскладки не тестировали (по условию — без установки хука и без админ-прав).
- UI/App не покрыты (вне зоны).
- Evaluate не измеряет многопоточную производительность и память; мкс/слово — однопоточная оценка на текущем железе, числа немного плавают между запусками (в пределах ±20 %).
- Критерий recall ≥ 98 % на «сырых» корпусах не достигнут из-за покрытия словаря (см. выше); на подмножестве с известным целевым словом — 100 %. Требуется решение lead: расширять словарь или менять политику порога для незнакомых кандидатов.
